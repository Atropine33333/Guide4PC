# 附录十七：隐私与安全

> 这个附录介绍网络通信的基本原理（HTTPS、TCP、TLS）、密码管理器、两步验证（2FA），以及一些容易被忽视的隐私习惯。不深入技术细节，但会让你知道“数据在网线里是怎么跑的”以及“怎么防止自己的账号被别人拿走”。

## 17.1 数据在网线里是怎么跑的：TCP、TLS、HTTPS

当你打开一个网站（比如 `https://www.baidu.com`），背后发生了三件事：建立连接、加密通道、传输数据。

### 17.1.1 TCP：建立可靠的连接

**TCP（Transmission Control Protocol，传输控制协议）** 负责把数据可靠地从一端送到另一端。它会先把数据拆成一个个小包，每个包编号，发送出去，等对方确认收到了再发下一个。如果某个包丢了，TCP 会重发。

可以这样理解：TCP 像寄挂号信——每一封都有编号，收件人要签收，没收到就再寄一次。优点是可靠，缺点是慢一点（因为有来来回回的确认）。

**和 UDP 的区别**：UDP 像寄普通明信片——扔进邮筒就不管了，不确认对方是否收到。优点是快，缺点是可能丢包。视频通话、在线游戏常用 UDP（偶尔丢一帧画面还能忍，但延迟不能高）。

### 17.1.2 TLS：给数据上锁

**TLS（Transport Layer Security，传输层安全协议）** 是 HTTPS 里面那个“S”。它在 TCP 连接之上加了一层加密。你发送的数据在离开电脑之前被加密成密文，到达服务器后再解密。中间任何节点（路由器、运营商、Wi-Fi 热点）看到的都是乱码，无法读取内容。

TLS 的工作流程大致是：
1. 你的电脑和服务器互相打招呼，协商加密算法
2. 服务器出示数字证书（证明“我真的是百度”）
3. 双方生成一个共同的会话密钥（只有你们两个知道）
4. 之后的所有通信都用这个密钥加密

这就是为什么你在公共 Wi-Fi 里登录网银、输密码是相对安全的——数据是加密的，就算别人截获了也解不开。

### 17.1.3 HTTPS：HTTP + TLS

**HTTP（Hypertext Transfer Protocol，超文本传输协议）** 是浏览器和服务器之间传输网页内容的协议。但 HTTP 是明文传输，别人可以偷看。**HTTPS** 就是 HTTP 加上 TLS 加密。

**怎么看网站是不是 HTTPS**：地址栏前面有一个小锁图标。点开它可以看证书信息。

## 17.2 密码管理

### 17.2.1 为什么需要密码管理器

大多数人所有网站用同一个密码。只要其中一个网站数据库泄露（这种事经常发生），黑客就会用这个密码去试你的邮箱、微信、支付宝——这叫“撞库”。

密码管理器可以帮你：
- 为每个网站生成随机强密码（比如 `xK9#mQ2$pL5@nR8`）
- 自动填充登录框（不用记，也不用输）
- 同步到手机和电脑

### 17.2.2 Firefox 内置密码管理器

如果你用 Firefox 浏览器，自带的密码管理器就够用。

**开启同步**：注册 Firefox 账号，在设置里开启“同步”——密码、书签、历史会加密同步到你的其他设备（手机、另一台电脑）。

**查看/管理密码**：设置 → 隐私与安全 → 已保存的登录信息。可以在这里查看、删除、导出密码。

**主密码（Master Password）**：强烈建议设置一个“主密码”。Firefox 保存的密码默认是加密存储的，但只要你登录了 Windows，任何人打开 Firefox 就能看到你所有的密码。设置主密码后，每次打开 Firefox 或查看密码时需要输入一次主密码。路径：设置 → 隐私与安全 → 使用主密码。

**缺点**：Firefox 密码管理器只在 Firefox 浏览器里能用。如果你用其他浏览器或手机 App，它就帮不上忙了。

### 17.2.3 跨平台密码管理器

如果你需要跨浏览器、跨 App，可以试试：

- **Bitwarden**：开源、免费（高级版每年 10 美元）。支持 Windows、macOS、Linux、iOS、Android，浏览器插件全覆盖。可以自己搭建服务器（不推荐小白做）。这是目前个人用户最稳妥的选择。
- **KeePass**：纯本地存储，数据库文件放自己手里。功能强大但界面老气。需要手动同步数据库文件（用网盘）。
- **1Password**：收费。你可以读这一篇[博客](https://yishi.io/1password-complete-tutorial/) , ta写的很好。

### 17.2.4 绝对不能做的事

- ❌ 把密码写在便利贴上贴显示器
- ❌ 在微信/QQ里发密码截图
- ❌ 用“记住密码”功能但不设主密码（谁都能看你电脑）
- ❌ 所有网站用同一个密码

## 17.3 两步验证（2FA）

### 17.3.1 什么是 2FA

**2FA（Two-Factor Authentication，双因素认证）** 是在密码之外再加一层保护。登录时除了输密码，还要输入一个动态生成的 6 位数字验证码（通常 30 秒变一次）。即使别人偷了你的密码，没有这个验证码也登不上。

常用的 2FA 是 **TOTP（Time-based One-Time Password，基于时间的一次性密码）**。原理：你和服务器共享一个密钥，基于当前时间生成一个 6 位数字。因为时间不会骗人，双方算出来的数字一样。

### 17.3.2 微软验证器（Microsoft Authenticator）

微软验证器是比较好用的 2FA 工具之一。手机端免费，支持云备份（需要微软账号）。

**重要：换机前必须先解除 2FA 关联**

这是很多人在换手机时踩过的大坑。

假设你用微软验证器绑定了好几个账号——Google、GitHub、Steam、你的学校邮箱。你买了一部新 iPhone，用苹果的“一键换机”把数据迁移过去。迁移完成后，微软验证器也会被拷过来，**但是那些 2FA 密钥不会跟着迁移**。因为 TOTP 的密钥存储方式特殊，简单的“复制 App 数据”不包含密钥。

更麻烦的是：如果你的多个账号是互相绑定的——比如你登录 Google 需要 GitHub 验证码，登录 GitHub 需要 Google 验证码——换机后两边都登不上去，形成一个闭环。

**正确做法**：
1. 在换机之前，登录每一个绑定了 2FA 的网站
2. 进入账户安全设置，**把 2FA 关掉**（或者“删除此设备”）
3. 确认所有账号都解除绑定后，再换新手机
4. 新手机到手，重新安装微软验证器
5. 一个一个重新绑定 2FA（扫描二维码或手动输入密钥）

**如果已经换完了怎么办**：
- 大部分网站会提供“备用恢复码”——在你开启 2FA 时，网站会给你一组成串的字符，让你抄下来或打印出来。用恢复码可以登录进去，然后重新绑定。
- 如果你连恢复码都丢了，只能联系网站客服，提交身份证明（身份证、手持证件照片等），等对方帮你解绑。这个过程可能需要几天甚至几周。
- 所以在开启任何 2FA 时，**恢复码一定要存好**（打印出来，或者存到不是这台手机的地方）。

### 17.3.3 哪些账号值得开 2FA

- **邮箱**：你的 Gmail、Outlook、学校邮箱——因为很多网站用“忘记密码”往邮箱发重置链接。邮箱被攻破等于所有账号失守。
- **Apple ID / Google 账号 / 微软账号**：这些是你手机的钥匙。
- **Steam**：游戏库存值钱，Steam 被盗找回很麻烦。
- **GitHub**：如果你是计算机专业学生，代码仓库被删或被人塞恶意代码，后果严重。
- **密码管理器**：Bitwarden、1Password 等支持 2FA，建议开启。

**不建议开的**：那些你几乎不登录、丢了也无所谓的小论坛账号。

### 17.3.4 2FA 的备份方案

除了微软验证器，还有几个选择：

- **2FAS**：开源，支持 iOS/Android，有云备份（通过 iCloud/Google Drive），界面清爽。推荐。
- **Aegis**（仅安卓）：开源，支持备份到本地文件（加密后存到网盘），功能强大。

## 17.4 几个容易被忽略的隐私习惯

### 17.4.1 浏览器不要保存银行卡信息

Chrome/Edge 会问你是否保存信用卡信息以便下次自动填充。方便是方便，但谁打开了你的浏览器（或者你电脑被远程控制），就能看到你的完整卡号、有效期、甚至 CVV 码（部分版本）。

**建议**：不保存。自己输 16 位卡号也没多慢。

### 17.4.2 公共 Wi-Fi

咖啡馆、机场、酒店的公共 Wi-Fi 可能是钓鱼热点（别人架一个叫“Starbucks Wi-Fi”的假热点）。你连上去后，对方可以抓包你的 HTTP 流量。

**保护措施**：
- 尽量避免在公共 Wi-Fi 上输密码
- 如果一定要用，尽量访问 HTTPS 网站（小锁图标是绿的）
- 最安全的是用手机热点，或者挂自己的代理/VPN

### 17.4.3 屏幕锁

很多人没有设置电脑的屏幕锁（Windows 按 `Win + L` 锁屏）。在宿舍、实验室、图书馆，你走开接个水，别人就能坐你电脑前看你微信、邮件、论文。

**建议**：
- Windows：设置 → 账户 → 登录选项 → 添加 PIN 或密码
- 养成习惯：人离开，按 `Win + L`

# 补充阅读

> 以下内容涉及 HTTPS 证书、TLS 握手细节和密码学基础概念，难度较高。用到了再回来看。

## 补充1：数字证书与 CA

HTTPS 里的证书由 **CA（Certificate Authority，证书颁发机构）** 签发。你的操作系统和浏览器内置了一组受信任的 CA 根证书（如 DigiCert、Let's Encrypt、GlobalSign）。当你访问 `https://www.baidu.com` 时，服务器会出示一张证书，浏览器检查证书是否由某个受信任的 CA 签发、证书上的域名是否和正在访问的域名一致、证书是否过期。全部通过才会建立 TLS 连接。这也解释了为什么“下载未知来源的根证书”是危险行为——一旦安装了一个恶意 CA 证书，攻击者就可以伪造任何网站的证书，你的浏览器还会显示“安全”。

## 补充2：TLS 1.2 与 TLS 1.3 的区别

TLS 1.3 比 1.2 快一个往返时间（RTT）。TLS 1.2 需要两次握手（约 2 RTT）才能开始传输数据；TLS 1.3 简化了握手过程（1 RTT，甚至 0 RTT 恢复会话）。安全性也更高——移除了一些过时的加密算法（如 RSA 密钥交换、CBC 模式），强制使用前向保密（Forward Secrecy）的密钥交换算法。目前主流浏览器和服务器都已支持 TLS 1.3。

## 补充3：密码管理器加密原理

密码管理器存储的密码数据库是加密的（AES-256）。解密密钥由你的主密码派生而来。主密码不会存储在任何服务器上——Bitwarden、1Password 等采用零知识架构：服务器只存储加密后的数据块，没有你的主密码，他们自己也无法解密你的密码库。这也是为什么“忘记主密码”通常是不可恢复的——没有任何“找回密码”按钮。

## 补充4：TOTP 的时间同步问题

TOTP 依赖设备时间准确。如果你的手机时间比标准时间偏差超过 30 秒，生成的验证码会无效。手机开启“自动设置时间”通常没问题。如果发现验证码总是输错，去设置里校准时间。离线设备（如硬件令牌）也有内部的电池时钟，年头长了会漂移，需要重新同步。

## 补充5：恢复码的存储

开启 2FA 时网站给的恢复码（通常是 8-10 个单词或一串数字）是用来救命的。存储建议：
- 打印出来放在钱包里（不推荐放在电脑桌面）
- 保存在密码管理器里（Bitwarden 支持存储 2FA 恢复码的笔记）
- 保存在加密的笔记 App 里（如 Standard Notes、Joplin）
- 不要存在手机相册里（手机丢了就全丢）

## 补充6：钓鱼网站与 HTTPS 误区

HTTPS ≠ 网站可信。钓鱼网站也可以免费申请到 Let's Encrypt 的证书，地址栏照样有小锁图标。看到小锁只说明“你和这个网站的通信是加密的”，不代表“这个网站是合法的”。判断方法：检查域名拼写（`google.com` 还是 `g00gle.com`），看是不是和你平时访问的一模一样。
