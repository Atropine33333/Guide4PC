# 附录五：浏览器

> 本附录介绍浏览器的基本用法、搜索技巧、提问方法以及常用插件。

## 5.1 选哪个浏览器

Windows 系统自带 Microsoft Edge。它基于 Chromium 内核，兼容性好。直接使用即可。

Firefox 也很好用。

请 **不要** 下载任何国产浏览器，诸如360极速浏览器，2345浏览器

## 5.2 多线程下载：FDM

浏览器自带的下载是单线程。大文件下载速度慢，断线后可能需要从头开始。多线程下载工具将文件分成多块同时下载，速度更快，支持断点续传。

推荐使用 **FDM（Free Download Manager）**。免费、开源、无广告。安装时勾选浏览器集成插件。设置无需手动更改。下载大文件（几百 MB 以上）时，浏览器会自动调用 FDM。

[FDM](https://www.freedownloadmanager.org/)下载链接

## 5.3 搜索引擎

推荐使用 **必应**。国内可直接访问，广告比百度少。有条件使用 Google 的话，英文搜索更准确。

## 5.4 高效搜索技巧

搜索时不要输入完整句子，应提取关键词。

示例：
- 不好：`为什么我的电脑插了U盘之后鼠标动不了`
- 较好：`插入U盘后鼠标失灵`

有用的搜索指令：

| 指令 | 作用 | 示例 |
|------|------|------|
| `site:` | 限定网站 | `site:zhihu.com 笔记本 供电` |
| `filetype:` | 限定文件格式 | `filetype:pdf 数学分析` |
| `"双引号"` | 精确匹配 | `"如何安装Python"` |
| `-` 减号 | 排除词语 | `苹果 -手机` |

搜索错误信息时，直接复制完整的错误代码（如 `0x80070005`）比描述现象更有效。

## 5.5 信息真假判断

- 看来源：优先选官方、知名媒体。来历不明的自媒体账号需谨慎。
- 看日期：过时的信息可能已无效。
- 交叉验证：不同来源对比。
- 看评论区：有大量反对意见或事实纠错的，通常不可信。
- 警惕标题：带“震惊”“紧急”“删前速看”等字样的多半是标题党或谣言。

学术用途：使用 Google Scholar 或学校图书馆数据库。维基百科英文版的参考文献可作为参考。

## 5.6 提问方法与网络礼节

提问时尽量附上以下信息：
- **完整的错误提示**（文字或截图）
- **运行环境**：操作系统版本、软件版本、硬件型号等
- **日志文件（log）**：许多程序和游戏会在安装目录或 `%appdata%` 下生成 `.log` 文件，复制最后几十行附上

示例（游戏闪退）：
> 问题：启动某游戏后黑屏闪退  
> 环境：Windows 11 22H2，显卡驱动 610.47，游戏版本 1.2.3  
> 错误提示：`Fatal error: DXGI_ERROR_DEVICE_REMOVED`  
> 日志最后几行：[粘贴内容]  
> 已尝试：更新驱动、验证游戏文件完整性

基本礼节：
- 先尝试自己搜索，解决不了再提问。
- 问题描述清晰，说明已尝试过的方法。
- 得到帮助后回复结果，以便他人参考。
- 不要私信打扰，公共问题在公开渠道问。

## 5.7 常用浏览器插件

插件从浏览器官方商店安装（Edge 加载项、Chrome 网上应用店、Firefox 附加组件）。

### 5.7.1 广告屏蔽：uBlock Origin

开源、轻量，可屏蔽多数广告和跟踪器。对于经常访问的小网站或个人博客，如果广告不碍事，可以关掉 uBlock（点击插件图标 → 电源图标变灰）或将该网站加入白名单。这些网站靠广告维持运营。

### 5.7.2 猫抓（Cat Catch）

嗅探网页中的音视频真实地址，提供下载。当网页有媒体播放时，插件图标上会显示数字，点击即可选择下载。适用于在线课程录音、背景音乐等场景。

### 5.7.3 LeechBlock NG

限制访问某些网站的时间。可设置每日最大时长或允许的时段，达到限制后自动阻止。可用于控制刷社交媒体、视频网站的时间。

### 5.7.4 篡改猴（Tampermonkey）

用户脚本管理器。可从 GreasyFork（greasyfork.org）安装脚本，实现自动填表、去广告等自定义功能。

**安全提醒**：
- 不要安装来源不明的脚本，尤其是“免费看VIP”“抢购助手”等。
- 安装前查看脚本代码，如果请求很多外部权限（如 `@connect *`），不要安装。
- 不要安装非官方商店的插件，尤其是“免费 VPN”“网页加速器”等。

# 补充阅读

> 以下内容涉及浏览器底层机制和技术细节，难度较高。建议先快速扫一眼，知道有这些概念即可。后续遇到具体问题时，再用关键词搜索回来查阅。
> 对于疑惑或想进一步了解的部分，我建议自行查找[MDN](https://developer.mozilla.org)和[W3School](https://www.w3school.com.cn/index.html)

## 补充1：浏览器内核

浏览器内核（渲染引擎）负责将 HTML、CSS、JavaScript 代码转换成可见的页面。

- **Blink**：Chrome、Edge、Opera、Brave 等使用。目前市场占有率最高。
- **Gecko**：Firefox 使用，完全开源。
- **WebKit**：Safari 使用。Blink 最初从 WebKit 分支出来。

普通用户无需关心这些差异。极少数老旧网站可能提示“请使用 Chrome”，实际 Edge 也能正常打开。如果遇到某个网站显示错乱，可以尝试换一个浏览器。

## 补充2：网页结构（HTML、CSS、JavaScript）

网页由三种语言共同构成：

- **HTML**：定义内容和结构。浏览器将其解析成 DOM 树。
- **CSS**：定义样式和布局。控制颜色、字体、位置等。
- **JavaScript**：定义交互行为。点击按钮、轮播图、表单验证等都需要它。
  - **TypeScript**：JavaScript 的超集，增加了类型注解。需编译成 JS 运行。
  - **ES6**：JavaScript 的 2015 年版本，引入了箭头函数、类、模块等。现代浏览器均支持。

**响应式设计**：通过 CSS 媒体查询（`@media`）自动适配不同屏幕宽度。可在浏览器按 F12 → 点击设备模拟图标（小手机）查看手机版效果。

**渐进增强**：先保证基本内容（纯 HTML）在所有设备上可访问，再逐步添加样式和交互。对老旧设备和残障人士更友好。

## 补充3：响应头与状态码

浏览器请求网页后，服务器返回响应头。按 F12 → Network 标签 → 点击任意请求可查看。

常见状态码：
- **200**：成功
- **301**：永久重定向
- **302**（或 307）：临时重定向
- **403**：禁止访问
- **404**：页面不存在
- **500**：服务器内部错误

## 补充4：User-Agent（UA）

浏览器发送给服务器的标识字符串，包含浏览器名称、版本、操作系统。服务器可根据 UA 返回不同版本的页面（如手机版、电脑版）。

按 F12 → 设备模拟（选择一款手机型号），刷新页面即可伪装成手机。也可安装 UA 切换插件。注意不要用 UA 伪装去爬取网站数据，应遵守 `robots.txt` 协议。

## 补充5：Cookie、localStorage、IndexedDB

三种浏览器本地存储方式：

| 名称 | 容量 | 生命周期 | 是否随请求发送 | 主要用途 |
|------|------|----------|----------------|----------|
| Cookie | 4KB | 可设置过期时间 | 是 | 登录态、用户追踪 |
| localStorage | 5~10MB | 永久（除非手动清除） | 否 | 用户偏好、主题设置 |
| IndexedDB | 数百 MB | 永久 | 否 | 离线缓存大量结构化数据 |

**Cookie**：保存会话 ID，清除后需重新登录。
**localStorage**：API 简单，适合存储少量设置。
**IndexedDB**：支持索引和事务，但 API 复杂。许多 PWA 用它缓存数据。

查看和管理：F12 → Application → Storage 区域。

## 补充6：Chrome/Edge Flags 与 Firefox about:config

浏览器实验性功能入口：
- Chrome/Edge：地址栏输入 `chrome://flags` 或 `edge://flags`
- Firefox：地址栏输入 `about:config`，点击“接受风险”

修改后出现问题，点击“Reset all”恢复默认。

## 补充7：开发者工具（F12）主要面板

- **Elements**：查看和编辑 HTML/CSS（仅本地临时效果）。
- **Console**：显示 JS 错误、警告，可执行 JS 代码。
- **Sources**：查看源文件，设置断点调试 JS。
- **Network**：记录所有网络请求，查看状态码、耗时、请求内容。
- **Application**：管理 Cookie、localStorage、IndexedDB、Service Worker。
- **Performance**：录制性能数据，分析卡顿原因。
- **Lighthouse**：网页综合评分（性能、可访问性、SEO）。

## 补充8：Service Worker 与 PWA

**Service Worker**：浏览器后台运行的脚本，可拦截网络请求、管理缓存、推送通知。即使未打开网页也可运行。

**PWA（渐进式网页应用）**：使用 Service Worker 等技术，让网页具备类似原生应用的体验——可添加到桌面、离线使用、接收推送。当 Chrome/Edge 地址栏右侧出现安装图标（电脑屏幕加向下箭头）时，点击即可将网站安装为桌面应用。

## 补充9：CORS（跨域资源共享）

浏览器安全策略“同源策略”限制网页向不同域名发起请求。如果需要在不同域名间请求数据，目标服务器必须在响应头中包含 `Access-Control-Allow-Origin`。

开发本地网页时常遇到 CORS 错误。解决方法需要后端配置响应头或使用代理。了解这个概念有助于理解某些网页调用 API 失败的原因。

## 补充10：WebFonts、浏览器缓存与 WebAssembly（Wasm）

### WebFonts（网页字体）

网页上使用的字体（如 Noto Sans、思源黑体）通常不是操作系统自带的，需要从服务器下载。这些字体文件（`.woff2`、`.woff`、`.ttf`）称为 WebFonts。

- 网站通过 CSS 的 `@font-face` 规则声明需要下载的字体文件。
- 浏览器下载后缓存在本地，下次访问同一网站时无需重新下载。
- 常见格式：**WOFF2**（压缩率高，现代浏览器通用），**WOFF**（兼容旧浏览器），**TTF**（未压缩，较少用）。

如果某个网站文字闪烁或显示异常（如出现方框、乱码），可能是 WebFonts 加载失败。可以按 F12 → Network 标签筛选“Font”类型，查看字体请求是否返回 404。

### 浏览器缓存

浏览器缓存（HTTP Cache）是将已下载的资源（图片、CSS、JS、字体等）保存在本地磁盘。再次访问同一页面时，直接从本地读取，无需重新请求服务器，可大幅加快加载速度。

**缓存机制简析**：
- 服务器返回资源时，会在响应头中附带 `Cache-Control` 或 `Expires` 字段，指示浏览器可以缓存多长时间。
- 例如 `Cache-Control: max-age=86400` 表示资源在 24 小时内有效，期间浏览器直接使用缓存，不会向服务器发起请求。
- 当缓存过期后，浏览器会发起“条件请求”，用 `If-Modified-Since` 或 `ETag` 询问服务器资源是否有更新。若无更新，服务器返回 `304 Not Modified`，浏览器继续使用缓存。

**手动控制缓存**：

- 可以按 `Ctrl+F5` 使刷新时从服务器重新拉取资源。
- 按 F12 → Network → 勾选“Disable cache”（禁用缓存）可在调试时强制每次都从服务器拉取。
- 清除浏览器缓存：设置 → 隐私和安全 → 清除浏览数据 → 选择“缓存图片和文件”。

### WebAssembly（Wasm）

WebAssembly 是一种可以在浏览器中运行的二进制指令格式。它的设计目标是接近原生代码的执行速度，同时保证安全性。C、C++、Rust、Go 等语言都可以编译成 Wasm，然后在网页中通过 JavaScript 调用。

**为什么需要 Wasm？**  
传统 JavaScript 是解释执行的（虽然现代 JS 引擎有 JIT 编译），但对计算密集型任务（如视频编解码、图像处理、游戏物理引擎、加密运算）性能仍然不够。Wasm 提供了一种更底层的、可预编译的代码格式，执行效率明显更高。

**一个简单的 Wasm 示例**

下面演示如何编写一个 C 语言加法函数，编译成 Wasm，并在 HTML 中调用。

注意，以下代码仅供有编程基础的人参考

**步骤 1：编写 C 代码（`add.c`）**
```c
// 导出一个加法函数
int add(int a, int b) {
    return a + b;
}
```

**步骤 2：编译为 Wasm**  
安装 Emscripten 工具链后执行：
```bash
emcc add.c -o add.wasm -s EXPORTED_FUNCTIONS="['_add']" -s EXPORTED_RUNTIME_METHODS="['ccall']" --no-entry
```
生成 `add.wasm` 文件。

**步骤 3：在 HTML 中加载并调用**
```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>Wasm 加法示例</title>
</head>
<body>
    <script>
        // 加载 wasm 模块
        fetch('add.wasm')
            .then(response => response.arrayBuffer())
            .then(bytes => WebAssembly.instantiate(bytes))
            .then(results => {
                // 调用导出的 add 函数
                const result = results.instance.exports._add(3, 5);
                console.log('3 + 5 =', result);  // 输出 8
                document.body.innerHTML = '<p>3 + 5 = ' + result + '</p>';
            });
    </script>
</body>
</html>
```

**实际应用场景**：
- **Figma**：图形渲染引擎用 Wasm 实现。
- **AutoCAD Web**：CAD 软件的浏览器版。
- **视频/图像处理**：如 ffmpeg 编译为 Wasm 实现在线转码。
- **游戏引擎**：Unity、Unreal Engine 支持导出 Wasm 到网页。

对于普通用户，无需直接接触 Wasm。但了解它有助于知道“为什么某些网页应用运行得那么快”以及“为什么你的 CPU 占用突然升高”——可能是因为网页正在运行一个复杂的 Wasm 计算任务。
