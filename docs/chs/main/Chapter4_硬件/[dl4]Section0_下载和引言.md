## 0.1 项目简述

本项目会从硬件软件建模三方面一起入手，目的是完成一个可高度自定义的（因为毕竟程序是自己写的）基于 STM32G474CEx 系列 MCU 的 DSP 声卡。具体功能我现在还没有构思完，所以这里仅作为占位。

在这个项目中，你会学习到 ST 系列单片机的 HAL 基础写法，用于嵌入式的 C 语言的基础，一些代码优化思想，一些架构思想，RTOS 基础，硬件设计基础，建模基础应该是学不到了，因为我也在学习，所以这个模型应该也是比较粗糙的。

哦对了，其实你还能收获到关于如何做音频 DSP 的一点启发，但只是一点，因为我毕竟也不是专业人士。


## 0.2 杂谈

这个章节预计会很长很长，因为毕竟又要教 C 语言，而且嵌入式 C 语言会大量使用指针这个抽象的东西，还有有时候为了优化会采用一些难以看懂的写法，同时实时性也是不得不关注的一环，所以我会着重强调指针的本质、边界与常见陷阱，优化写法的可读性与可维护性，以及实时性约束下的编码习惯和工程取舍，尽量做到既讲清原理，又给出能落地的实践建议。当然，因为我也是学习者，所以相较传统教材，我难以做到尽善尽美，对于 PID 控制、数字信号处理、通信协议栈、RTOS 内核实现、硬件时序与电磁兼容、我现有水平也难以讲透，建议研读相应专著。

我将会以 `STM32CubeCLT(含STLinkServer) + VSCode` 为工具链进行开发和调试。我会在第一节讲述如何搭建该环境。

另外，值得点评的是，有一部分团队对于开发 ST 系列单片机有一些自己*独到*的想法，摒弃了传统基于 `Keil μVersion 5` 的开发路径，但是也并未完全拥抱更现代的基于 `STM32CubeCLT(含STLinkServer) + VSCode` 的工具链，同样也没有使用更加通用和现代化的 `VSCode + GCC + OpenOCD + GDB` 工具链，而是采用了令人感到十分困惑的 `Keil + VSCode + mingw-w64-ucrt-x86_64-gcc` 工具链。请读者注意，这个环境配置是典型的反面案例，它本质上还是基于 `Keil` 这个调试体验并不好的 IDE，只是难以忍受他丑陋的界面于是为他披上了一层 `VSCode` 的皮囊，并使用了实在令人费解的 `mingw-w64-ucrt-x86_64-gcc` 这个 x86_64 版本的 mingw 作为 IntelliSense。值得注意的是，一般来讲，就普遍而论，ST 主流系列单片机均采用了 arm 架构，所以这个 x86_64 版本的 mingw 无疑是令人费解的。接下来是一些截图，**请读者注意，不要模仿这些图片里令人困惑的操作**。
