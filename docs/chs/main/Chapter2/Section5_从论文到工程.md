## 5.1 从论文公式到可执行代码的抽象过程

论文里的偏微分方程是数学语言，计算机不认识。程序员的第一个任务就是把那几行公式翻译成数据结构和算法步骤。

**论文中的核心公式（热传导方程）：**

\[
\frac{\partial T}{\partial t} = \alpha(x,y)\left(\frac{\partial^2T}{\partial x^2} + \frac{\partial^2T}{\partial y^2}\right) + S(x,y)
\]

这个公式描述了温度随时间的演化。要让计算机执行它，必须完成以下抽象：

**步骤1：离散化 → 把连续变成离散**

| 连续概念 | 离散实现 |
| :--- | :--- |
| 连续空间 \((x,y)\) | 网格点 \((i,j)\)，\(x_i=i\cdot\Delta x,\ y_j=j\cdot\Delta y\) |
| 连续时间 \(t\) | 时间步 \(n\)，\(t_n=n\cdot\Delta t\) |
| 温度场 \(T(x,y,t)\) | 数组 \(T_{i,j}^{(n)}\)，存在 `Grid2D` 里 |
| 热扩散率 \(\alpha(x,y)\) | 数组 \(\alpha_{i,j}\)，存在另一个 `Grid2D` 里 |
| 热源 \(S(x,y)\) | 数组 \(S_{i,j}\)，预计算后存好 |
| 拉普拉斯算子 \(\Delta T\) | 五点差分模板（见5.3节） |
| 时间导数 \(\partial T/\partial t\) | 前向欧拉差分 \(T^{n+1} = T^n + \Delta t \cdot (\cdots)\) |

**步骤2：正演 → 前向迭代**

```cpp
// 每一轮时间步，遍历所有内点，用旧值计算新值
for (int k = 0; k < sim_steps; ++k) {
    for (int j = 1; j < ny-1; ++j)
        for (int i = 1; i < nx-1; ++i)
            T_new.at(i,j) = T_old.at(i,j) + dt * (Alpha.at(i,j) * lap + Source.at(i,j));
}
```

这个过程就是**正演**——给定参数算温度。

**步骤3：反演 → 逆向优化**

论文中提到的“逆问题”，在工程上被转化为一个**优化问题**：

\[
\alpha^* = \arg\min_\alpha \sum_t \|T_\text{pred}(\alpha, t) - T_\text{obs}(t)\|^2
\]

翻译成代码就是：

```cpp
// 1. 猜一个初始 α（通常设为均匀值）
// 2. 算损失：正演一次，比较预测温度和观测温度
// 3. 算梯度：扰动每个网格点的 α，看损失怎么变化
// 4. 更新：沿梯度反方向调整 α
// 5. 重复 2-4 直到损失足够小
```

这个“三步曲”是整个工程的核心逻辑：**离散化 → 正演 → 反演**。论文给出了数学描述，工程实现了可运行的代码。

## 5.2 构造系数场：为什么这样设计真值

反演问题的验证方法是：先构造一个已知的真值（Ground Truth），模拟生成观测数据，然后看算法能否从数据中恢复出这个真值。如果连已知答案都找不回来，面对真实数据更不可能成功。

**本工程的真值设计：**

```cpp
// 左半区域（x < 0.5）：低导热率 0.1（模拟隔热层/空气隙）
// 右半区域（x ≥ 0.5）：高导热率 0.8（模拟铜）

for (int j = 0; j < NY; ++j) {
    for (int i = 0; i < NX; ++i) {
        Alpha_true.at(i,j) = (i * dx < 0.5) ? 0.1 : 0.8;
    }
}
```

**为什么选择“左右两半”这种分布：**

1. **有一个清晰的界面**：在 \(x=0.5\) 处存在一个锐利界面，左半导热慢、右半导热快。这种不连续性是反演中最难恢复的特征——神经网络倾向于输出平滑解，而 DeepFDM 的网格直接存储每个点的 α，可以天然地捕捉间断。

2. **物理上可解释**：低导热区可以理解为隔热材料、空气隙或损伤区域，高导热区为金属基体。这是工程无损检测中的真实场景——寻找材料内部的缺陷（空洞、裂纹、夹杂物）。

3. **初始猜测 \(\alpha=0.5\) 并非随意选取**：介于 0.1 和 0.8 之间，给了算法“向左走还是向右走”的自由。如果初始猜测是 0.1，左半可能收敛快但右半需要爬升；如果是 0.8，右半快但左半要下降。0.5 是最小化初始偏差的选择。

## 5.3 显式欧拉格式：为什么选最简单的方案

论文中提到了 Forward Euler 方法，工程上直接选用它，基于以下权衡：

**显式欧拉的实现极简：**

```cpp
T.at(i,j) = T_old.at(i,j) + dt * (Alpha.at(i,j) * lap + Source.at(i,j));
```

一行代码就是一个时间步的更新公式，无需解线性方程组，代码直接对应数学公式，几乎不会写错。

**为什么不选更复杂的时间格式（如 Crank-Nicolson 或 Runge-Kutta）：**

| 方案 | 优点 | 缺点 | 本工程的取舍 |
| :--- | :--- | :--- | :--- |
| 显式欧拉 | 实现简单，每步 O(N) | 时间步长受 CFL 限制 | ✅ 选用，代码清晰 |
| Crank-Nicolson | 无条件稳定，步长可大 | 需解线性方程组，代码复杂 10 倍 | ❌ 不选用 |
| RK4 | 高阶精度（O(Δt⁴)） | 每步需 4 次右端项计算，反演梯度成本翻 4 倍 | ❌ 不选用 |
| 自适应步长 | 自动调整效率高 | 梯度计算时步长不固定，难以比较 | ❌ 不选用 |

**反演场景的特殊性放大了显式格式的优势**：
梯度计算需要 1600 次正演，如果每次正演都要解线性系统（隐式格式）或额外算 4 次右端项（RK4），总计算量会从 1600×8000 步变成 1600×8000×（数十倍），从“2 分钟”变成“2 小时”。显式格式虽然时间步长小，但每一步计算量极轻，在反演这种“做一万次正演”的场景下总体最优。

## 5.4 拉普拉斯算子的离散与边界条件的工程实现

**五点星形模板的代码：**

```cpp
double lap = (T_old.at(i-1, j) + T_old.at(i+1, j) +
              T_old.at(i, j-1) + T_old.at(i, j+1) -
              4.0 * T_old.at(i, j)) / (dx * dx);
```

这个模板只用了正交的四个邻居，没有用对角点（如 `(i-1,j-1)`）。为什么？

- **二阶精度足够**：该模板截断误差为 \(O(\Delta x^2)\)。网格从 40×20 加密到 80×40 时，误差减小到 1/4，精度已经足够识别 α 的左右差异。
- **计算量小**：五点模板只用 5 次内存访问。如果改用九点模板（含对角），需要 9 次访问，计算量几乎翻倍，但精度提升有限。
- **各向同性**：在正方形网格上，这个模板对 x 和 y 方向完全对称，不会引入方向性偏差。

**边界条件的工程处理：**

```cpp
// 循环只处理内点（i=1..nx-2, j=1..ny-2）
for (int j = 1; j < T.ny - 1; ++j) {
    for (int i = 1; i < T.nx - 1; ++i) {
        // ... 更新内点 ...
    }
}
// 每步结束后强制边界归零
T.setBoundary(0.0);
```

**为什么边界单独处理而不是在循环中加 if 判断：**

如果在内点循环里加 `if (i==0 || i==nx-1 || j==0 || j==ny-1)`，每次迭代都要做条件判断。800 个点 × 8000 步 × 1600 次正演 ≈ 102 亿次判断，累积开销巨大。边界只有 2×40+2×20-4=116 个点（占 14.5%），单独循环处理这 116 点，让主循环（684 个点）无分支运行，CPU 流水线效率最高。

## 5.5 将逆问题转化为优化问题

论文中说“反演是 ill-posed”，工程上需要把它变成一个“可计算”的问题。本工程采用的方法是用**均方误差 + 梯度下降**来求解。

**损失函数的设计：**

```cpp
// 单一时间点 MSE
double mse = (1.0 / N) * Σ (T_pred[k] - T_target[k])²
```

这看起来很简单，但**为什么要用平方误差而非绝对值误差**？

- 平方误差对大偏差的惩罚更重（差 2 的惩罚是 4，差 0.5 的惩罚是 0.25），促使优化器优先消除大误差。
- 平方误差的导数是连续的：\(\partial(\text{MSE})/\partial T = 2(T_{pred} - T_{target})/N\)。绝对值误差在零点不可导，会给梯度计算带来数值问题。
- 平方误差在统计上对应**高斯噪声假设**——如果观测误差服从正态分布，MSE 就是最大似然估计。

**实际代码中的损失是“多时间平均”的：**

```cpp
// 每 500 步记录一次，共 16 个记录点
for (int k = 1; k <= sim_steps; ++k) {
    solver.stepForward(T_pred, Alpha, Source, vx, vy);
    if (k % record_every == 0) {
        loss_sum += computeMSE(T_pred, target_records[rec_idx++]);
    }
}
return loss_sum / rec_idx;  // 16 个时刻的平均
```

如果只比较最终时刻，反演问题的“解空间”非常大——很多不同的 α 分布在终点温度上可能差异不大，因为扩散过程已经抹平了早期细节。加上中间时刻后，优化器必须同时匹配所有时间点的温度，约束更强，解更唯一。

## 5.6 为什么需要 8000 步正演

从代码中看到，`steps_target = 8000`，`record_every = 500`，共记录 16 个时刻。

**8000 步怎么定出来的：**

```cpp
// 物理时间 = 时间步长 × 步数
dt_true = 0.5 * (dx * dx) / (4.0 * max_alpha)
        = 0.5 * (0.0256²) / (4.0 * 0.8)
        ≈ 0.0001027 秒/步

物理总时间 = 8000 × 0.0001027 ≈ 0.822 秒
```

为什么要算到 0.8 秒？

- 热量从热源位置（x=0.3）扩散到整个区域（Lx=1.0）的特征时间约为 \(L_x^2 / \alpha \approx 1.0^2 / 0.8 = 1.25\) 秒。0.8 秒能覆盖从热源扩散到大部分区域的过程。
- 如果步数太少（如 2000 步，物理时间 0.2 秒），热量还没扩散到右边界，观测数据只包含热源附近的信息，难以反演右侧高导热区的 α 值。
- 如果步数太多（如 20000 步），系统已接近稳态（温度不再变化），额外的时间步只增加计算成本，不提供新信息。

```cpp
// 反演时的时间步长会根据当前猜测的 Alpha 重新计算
double max_a = *std::max_element(Alpha.data.begin(), Alpha.data.end());
double dt_crit = solver_template->dx * solver_template->dx / (4.0 * max_a);
double dt_safe = 0.5 * dt_crit;
```

注意：**反演过程中的时间步长和生成真值时的不同！** 如果当前猜测的 α_max 比真值大（比如 0.6），`dt_safe` 会比真值正演的 `dt_true` 小，这意味着同样的 8000 步物理时间变短了。这会导致预测的温度演化落后于观测，损失变大。这个偏差恰好提供了梯度方向——优化器会倾向于降低 α_max 来让时间步长变长，使演化速度匹配观测。

## 5.7 梯度计算的工程实现

论文没有给出梯度的计算方法，需要工程上自己选择。本工程用的方法是**有限差分中心扰动**。

```cpp
#pragma omp parallel
{
    // 每个线程有自己的求解器副本
    HeatSolver local_solver(solver_template->dx, solver_template->dy, dt_safe);
    Grid2D T_pred(nx, ny);
    Grid2D Alpha_pert(nx, ny);
    Alpha_pert.copyFrom(Alpha_backup);

    #pragma omp for collapse(2) schedule(dynamic)
    for (int j = 0; j < ny; ++j) {
        for (int i = 0; i < nx; ++i) {
            double orig = Alpha_backup.at(i, j);

            // +ε 扰动
            Alpha_pert.at(i, j) = orig + eps;
            double Lplus = runSimulation(T_pred, Alpha_pert, ...);

            // -ε 扰动
            Alpha_pert.at(i, j) = orig - eps;
            double Lminus = runSimulation(T_pred, Alpha_pert, ...);

            Alpha_pert.at(i, j) = orig;
            grad.at(i, j) = (Lplus - Lminus) / (2.0 * eps);
        }
    }
}
```

**工程权衡：为什么不用自动微分（Automatic Differentiation）？**

如果使用 TensorFlow/PyTorch 这样的框架，自动微分是内置的。但本工程是纯 C++ 实现（无第三方依赖），手动实现自动微分需要引入计算图、反向传播等复杂基础设施，代码量从 500 行膨胀到 5000 行。有限差分扰动法虽然计算量大（多 1600 倍），但实现极简、逻辑清晰、没有依赖。考虑到网格只有 800 个点，1600 次正演在 8 核 CPU 上并行后约需 1-2 分钟，完全可接受。

**为什么扰动步长取 0.01：**

| eps 取值 | 问题 |
| :--- | :--- |
| 太小（如 1e-8） | \(L_{+\epsilon} - L_{-\epsilon}\) 在双精度下接近舍入误差量级，梯度计算被噪声淹没 |
| 太大（如 0.1） | 扰动超出了局部线性区，中心差分公式的截断误差过大 |
| 0.01（本工程） | 平衡了截断误差和舍入误差，且在验证中收敛稳定 |

## 5.8 RMSprop + 梯度裁剪：为什么这样组合

**为什么不用纯 SGD：**

```cpp
// 纯 SGD 的更新
Alpha -= lr * grad;
```

800 个参数，每个参数的梯度量级差异巨大。热源中心的 α 对损失极度敏感（梯度大），远离热源的 α 几乎不受影响（梯度小）。纯 SGD 用统一学习率会导致中心点振荡、边角点几乎不动。

**RMSprop 解决这个问题：**

```cpp
// 每个参数维护自己的历史梯度平方的移动平均
grad_sq_avg.at(i,j) = rho * grad_sq_avg.at(i,j) + (1.0 - rho) * g * g;
grad.at(i,j) = g / (std::sqrt(grad_sq_avg.at(i,j)) + eps_rms);
```

如果一个参数的梯度一直很大，`grad_sq_avg` 也大，归一化后有效步长自动缩小。反之，如果梯度一直很小，有效步长自动放大。这让优化器对参数的“身份”无感：不管你是热源中心还是远离热源的角落，你的更新幅度都在同一个量级。

**梯度裁剪的作用：**

即使有 RMSprop，偶尔也会出现单点梯度异常（比如数值噪声导致某个点的梯度是正常值的 100 倍）。如果不处理，这一点的 α 会从 0.5 跳到接近 0.001 或 1.0，破坏整个训练。裁剪到 [-1,1] 相当于加了一道“保险丝”。

## 5.9 并行策略：OpenMP 的工程选型

800 个网格点，每个点需要 2 次正演，每次正演 8000 步。总计算量 = 800 × 2 × 8000 = 1280 万步网格更新。如果串行执行，在 3GHz 的 CPU 上约需数分钟。OpenMP 可以把这些工作分给 8 个核心，缩短到 30 秒左右。

**为什么用 OpenMP 而不是更复杂的方案：**

| 方案 | 优点 | 缺点 | 本工程适用性 |
| :--- | :--- | :--- | :--- |
| OpenMP | 修改代码极少（几行 #pragma），跨平台，共享内存通信成本低 | 只能单机多核，不能集群 | ✅ 选用了 |
| MPI | 可以跨多台机器，理论上无限扩展 | 需要改大量代码，通信开销大 | ❌ 800 个点杀鸡用牛刀 |
| CUDA | GPU 并行极快（理论千核） | 需要支持 CUDA 的显卡，编程模型差异大 | ❌ 为了通用性不引入 GPU 依赖 |

**OpenMP 代码的成本与收益：**

```cpp
// 增加 3 行代码，获得约 6-7 倍加速
#pragma omp parallel
{
    // ... 
    #pragma omp for collapse(2) schedule(dynamic)
    // ...
}
```

- 成本：需要编译器支持 `-fopenmp`，代码增加了“非标准”的 `#pragma`。
- 收益：训练时间从 7 分钟降到 1 分钟。
- 对于 800 点 × 2 扰动 × 8000 步的问题，这是极其划算的“投入产出比”。
