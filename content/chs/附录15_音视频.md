# 附录十五：音视频

> 这个附录介绍音视频处理的基本概念和常用工具。包括编解码器、容器格式、码率、OBS 录屏设置，以及剪辑软件的选择。后面的补充阅读留给 FFmpeg 命令行用法和更深入的技术概念。

## 15.1 编解码器（Codec）

**编码器（Encoder）** 把原始音视频数据压缩成某种格式。**解码器（Decoder）** 把压缩后的数据还原成可以播放的信号。

### 15.1.1 视频编解码器

| 名称 | 常见编码器 | 一句话说明 |
|------|-----------|------------|
| **H.264 / AVC** | `libx264`（软件）、`h264_nvenc`（N卡）、`h264_qsv`（Intel核显） | 兼容性最好，几乎所有设备都能播。 |
| **H.265 / HEVC** | `libx265`（软件）、`hevc_nvenc`（N卡）、`hevc_qsv`（Intel核显） | 同等画质下文件比 H.264 小。 |
| **AV1** | `libsvtav1`、`libaom-av1`（软件） | 压缩率更高，适合在线流媒体。 |

**提醒**：`hevc_nvenc` 需要 NVIDIA 显卡，`hevc_qsv` 需要 Intel 核显。不是所有电脑都有。

**软件编码 vs 硬件编码**：
- 软件编码（`libx264`、`libx265`、`libsvtav1`）：画质好、体积小，但吃 CPU，速度慢。适合精压制片、存档。
- 硬件编码（`hevc_nvenc`、`hevc_qsv`）：速度快（比软件快 5-10 倍），但同等码率下画质稍差。适合录屏、直播、快速导出。

### 15.1.2 音频编解码器

| 名称 | 常见编码器 | 一句话说明 |
|------|-----------|------------|
| **AAC** | `aac` | 目前最通用的音频格式，几乎所有视频都用它。 |
| **MP3** | `libmp3lame` | 老格式，兼容性好，但同码率下音质不如 AAC。 |
| **FLAC** | `flac` | 无损压缩，体积大，适合存档、听歌。 |
| **Opus** | `libopus` | 新技术，音质好压缩率高，部分老设备不支持。 |

## 15.2 容器格式（Container）

**容器格式** 是装视频、音频、字幕的“盒子”。同一个 H.265 编码的视频，可以放进 `.mp4`，也可以放进 `.mkv`。

| 容器 | 特点 |
|------|------|
| **MP4** | 最通用，几乎所有设备都能播。缺点：通常只能装一条视频、一条音轨、一条字幕。 |
| **MKV** | 功能强大，可以装多音轨、多字幕、章节信息。损坏后恢复能力强（只有最后几秒坏掉）。 |
| **MOV** | 苹果的 QuickTime 格式，也支持多轨道。适合在苹果设备和 Windows 之间交换。 |

## 15.3 码率（Bitrate）

码率是视频每秒的数据量，单位 **kbps**（千比特每秒）或 **Mbps**（兆比特每秒）。码率越高，画质越好，文件越大。

- **CBR（固定码率）**：从头到尾码率不变。适合直播。
- **VBR（可变码率）**：简单画面给低码率，复杂画面给高码率。同等平均码率下画质更好。
- **CRF（恒定质量）**：编码器自动分配码率，保证每一帧的质量大致相同。日常压制最省心。

## 15.4 OBS 录屏设置

### 15.4.1 基础设置

- **输出模式**：高级 → 输出设为“输出到文件”
- **容器格式**：选 **MKV**（原因：如果录制过程中软件崩溃或断电，MKV 只会损坏最后几秒；MP4 会全坏）
- **编码器**：
  - 有 Intel 核显 + 独显 → 选 **QuickSync HEVC**（用核显编码，不占用独显资源，对游戏帧数影响最小）
  - 只有 N 卡 → 选 **NVENC HEVC**
  - 只有 A 卡 → 选 **AMD AMF HEVC**（祝你好运）

### 15.4.2 参数建议

| 分辨率 | 码率 | 帧率 | 关键帧间隔 | B 帧 |
|--------|------|------|------------|------|
| 1080p | 35 Mbps | 60 fps | 3 秒 | 3 |
| 4K | 90 Mbps | 60 fps | 3 秒 | 3 |

游戏画面没有动态模糊，每一帧都是瞬间截图，快速移动时细节容易崩。所以游戏录制的码率要比普通视频高。

**关于 B 帧**：B 帧（双向预测帧）可以提高压缩率，但会增加编码延迟。设为 3 是在画质和兼容性之间的平衡。

### 15.4.3 管理员权限

对于某些全屏游戏，如果 OBS 捕获不到画面，**请右键以管理员身份运行 OBS**。

### 15.5.2 DaVinci Resolve

Blackmagic Design 出品的专业剪辑调色软件。**免费版已经非常强大**——剪辑、调色（好莱坞电影在用）、Fairlight 音频、Fusion 特效全流程整合。对色彩要求高的情况下，这款比 Premiere 更合适。

### 15.5.3 开源替代

如果你不想花钱，也不想折腾盗版，下面这三个开源软件值得一试：

#### Clypra

Clypra 是一款基于 Tauri + React + TypeScript + Rust + FFmpeg 构建的现代开源视频编辑器，采用 MIT 许可证。目标是免费复刻剪映国际版（CapCut）的付费功能。它没有使用 Electron（资源占用高），因此启动速度和内存占用都比同类工具有优势。

**核心功能**：
- 多轨道专业时间轴，支持拖拽剪辑、帧级精确裁剪
- 实时音频波形显示，方便卡点
- 胶片预览条（Filmstrip），通过缩略图快速定位内容
- 文字字幕与标题，支持自定义字体
- 项目管理与自动保存，100 级撤销/重做
- 支持 MP4、MOV、MKV、AVI 等视频格式，MP3、WAV、AAC 等音频格式
- 跨平台：Windows、macOS、Linux

**尚未实现**：AI 自动字幕、特效转场库、色彩分级、绿幕去背（开发中）。

> 适合谁：**短视频创作者、自媒体新手、不想付费给剪映的人**。基础剪辑已经够用。

**官网**：GitHub 搜索 `AIEraDev/Clypra`

#### Audacity

Audacity 是一款历史悠久、易于上手的开源多轨音频编辑器和录音软件，基于 GPLv3 许可证，支持 Windows、macOS、Linux。

**核心功能**：
- 多轨编辑，支持无限轨道
- 导入导出 WAV、AIFF、MP3、OGG、FLAC 等主流格式（通过 FFmpeg 可支持 MOV、M4A 等）
- 高质量录音（24bit/96kHz）
- 内置降噪、均衡器、压缩器、限制器等效果器
- 人声消除（Vocal Remover），利用相位抵消分离人声与伴奏
- 支持 VST2/VST3、LV2、Audio Units 插件
- Nyquist 脚本：用 Lisp 方言编写自定义音频处理

> 适合谁：**播客制作者、音乐爱好者、录音新手、偶尔修音的人**。它是“音频里的记事本”——不华丽，但什么都能干一点。

**官网**：`audacityteam.org`

#### Ardour

Ardour 是一款免费开源的数字音频工作站（DAW），功能对标 Pro Tools、Logic 等专业软件，支持 macOS、Windows 和 Linux。版本已迭代至 9.0。

**核心功能**：
- 录音与 MIDI 编曲：支持多通道同步录音（24 通道以上），任意数量的音轨和总线
- 非线性编辑：无损编辑，无限撤销/重做
- 专业级混音：浮点精度混音架构、发送与返送、自动化控制
- 插件格式全面：AudioUnit、LV2、VST2/VST3、LADSPA
- 高度灵活的信号路由：任意到任意的连接
- 与视频同步：采样级精确同步，适合电影/游戏音效制作
- 丰富的 MIDI 编辑功能（8.0 新增）：和弦编辑、量化、力度图等
- Clip Launching 模式（7.0 新增）：类似 Ableton Live 的 loop 回放

**系统要求**：推荐 2GB 以上内存，安装约 600MB 空间。

> 适合谁：**音乐制作人、播客重度用户、电影/游戏音效工作者、对音频有专业追求的人**。学习曲线陡峭，但功能深度是 Audacity 无法比拟的。

**官网**：`ardour.org`

## 15.6 HDR 与色彩联动

从附录十四我们知道，Windows 的色彩管理比较麻烦。HDR 视频剪辑更是如此：

- **HDR10**：基础 HDR 标准，10-bit 色深，静态元数据。多数 HDR 显示器支持。
- **杜比视界（Dolby Vision）**：更高级的标准，动态元数据（每帧亮度信息可不同），需要硬件和软件双端授权。
- **HLG**：适合广播电视的 HDR 标准，无需元数据，兼容 SDR 显示器。

如果你对 HDR 视频剪辑有严肃需求，**MacBook Pro 是目前最省心的选择**（XDR 屏幕，峰值亮度 1600 尼特，系统级色彩管理）。在 Windows 下折腾 HDR 的时间成本可能远高于预期。

## 补充1：FFmpeg 命令行工具

FFmpeg 是一个开源的命令行音视频处理工具。几乎所有音视频软件的底层都用到了它。转格式、剪片段、压字幕，一行命令就能搞定。

### 安装

从 [ffmpeg.org](https://ffmpeg.org/download.html) 下载 Windows 预编译包，解压后将 `bin` 文件夹添加到系统 PATH。打开命令行输入 `ffmpeg -version` 确认。

### 常用命令

**格式转换**：

```bash
ffmpeg -i input.mkv output.mp4
```

**视频裁剪**（从 1 分 30 秒开始，裁 45 秒）：

```bash
# 快速裁剪（可能不精确，但速度快）
ffmpeg -ss 00:01:30 -i input.mp4 -t 45 -c copy output.mp4

# 精确裁剪（会重新编码，慢但精确）
ffmpeg -i input.mp4 -ss 00:01:30 -t 45 -c:v libx264 -c:a aac output.mp4
```

> 参数说明：`-ss` 起始时间，`-t` 持续时长，`-c copy` 不重新编码（直接拷贝流）。`-ss` 放在 `-i` 之前是快速搜索（基于关键帧），放在之后是精确搜索（逐帧解码）。

**压制 HEVC**（软件编码）：

```bash
ffmpeg -i input.mp4 -c:v libx265 -crf 23 -c:a aac output.mp4
```

**使用 NVIDIA 显卡硬件编码**（如果显卡支持）：

```bash
ffmpeg -i input.mp4 -c:v hevc_nvenc -crf 23 -c:a aac output.mp4
```

**使用 Intel 核显硬件编码**（如果核显支持）：

```bash
ffmpeg -i input.mp4 -c:v hevc_qsv -crf 23 -c:a aac output.mp4
```

**提取音频**：

```bash
ffmpeg -i input.mp4 -vn -c:a aac -b:a 192k output.aac
```

`-vn` 表示不要视频流，`-b:a` 表示音频码率。

**下载 m3u8 视频**（在线流媒体）：

```bash
ffmpeg -i "https://example.com/stream.m3u8" -c copy output.mp4
```

### 批量处理

写一个简单的 Windows 批处理脚本（`.bat`）：

```batch
@echo off
for %%f in (*.mp4) do (
    ffmpeg -i "%%f" -c:v libx265 -crf 23 -c:a aac "%%~nf_hevc.mp4"
)
```

更复杂的任务可以用 PowerShell 7 脚本（支持 `ForEach-Object -Parallel` 并行处理）或 Python 调用 `subprocess`。FFmpeg 的强大之处在于：除去需要实时预览的调色等操作（其实也可以快速逐帧生成图片预览），其余的粗剪、转码、拼接、滤镜等，没有它干不了的。

## 补充2：I 帧、P 帧、B 帧的详细原理

视频压缩不存储每一帧完整画面，而是存储帧之间的“变化”。

- **I 帧（关键帧，Intra-frame）**：完整存储一帧画面。体积最大，解码最快。视频里的“完整图像”。每间隔一定帧数就会出现一个 I 帧（由“关键帧间隔”参数控制）。
- **P 帧（前向预测帧，Predicted frame）**：只存储和**前一帧**的差异。体积中等，解码时需要参考前面的 I 帧或 P 帧。
- **B 帧（双向预测帧，Bidirectional frame）**：同时参考**前一帧和后一帧**，存储双向差异。体积最小，压缩率最高，但解码最慢。

**为什么切在非 I 帧会花屏**：P 帧和 B 帧只存了“变化”，没有完整画面。如果从 P 帧或 B 帧开始播放，解码器不知道前面是什么样子，只能猜测，画面上就会出现破碎的方块。所以在不重新编码的情况下裁剪视频，只能从 I 帧切。如果需要精确到任意帧的切割，必须重新编码。

## 补充3：编码器速度预设

x264/x265 的 `-preset` 参数从 `ultrafast` 到 `placebo`，越慢画质越好（同等码率下）。日常用 `medium` 或 `slow`。`slower` 以上的收益已经很小。

- `ultrafast`：编码极快，画质差，体积大
- `medium`：默认，平衡速度与质量
- `slow`：比 medium 慢约 50%，码率可节省 5%-10%
- `veryslow`：很慢，收益递减

NVENC 的 `-preset` 有 `p1`（最快）到 `p7`（最慢，最好画质），默认 `p4`。`p7` 下画质有提升，但编码速度明显下降。

## 补充4：AV1 编码器对比

- **libaom-av1**：AV1 的参考编码器，画质最好，但编码速度非常慢（编码 1 秒视频可能需几分钟到几十分钟）。
- **libsvtav1**：英特尔主导开发的版本，编码速度快得多（比 libaom 快几百倍），画质也相当不错。日常压制 AV1 用 libsvtav1 即可。

## 补充5：2-pass 编码

第一遍分析视频，记录每一帧的复杂度；第二遍据此分配码率，在复杂场景给更多码率，简单场景给更少。适合需要精确控制输出文件大小的场景（例如上传网站有容量限制）。日常用 CRF 就够了，不需要二压。

## 补充6：杜比音频格式详情

- **AC-3**：老一代杜比数字音频，DVD 时代的标准，5.1 声道，码率通常 448k 或 640k。
- **E-AC-3（Dolby Digital Plus）**：杜比的有损环绕声，支持 5.1、7.1 声道，流媒体平台（Netflix、Disney+ 等）常用。码率通常 192k-768k。文件后缀可能是 `.ec3`。
- **TrueHD**：杜比的无损环绕声格式，常见于蓝光原盘，体积大，需要 HDMI 或 eARC 才能直通。支持最多 7.1 声道。

## 补充7：硬件编码器支持检测

GitHub 上有 **HwCodecDetect** 工具，可以一键检测你的电脑支持哪些硬件编码器和解码器，以及它们能处理到多大分辨率。

```bash
pip install hwcodecdetect
hwcodecdetect
```

它会输出一份报告，列明 NVENC、QSV、AMF、VAAPI、VideoToolbox 等各种接口的编码支持情况。

## 补充8：FFmpeg 流拷贝的坑

`-c copy` 不重新编码，速度极快且无损。但裁剪视频时如果起始点不是 I 帧，FFmpeg 会从上一个 I 帧开始拷贝，导致你得到的片段开头比预期早了零点几秒。处理方法：
- 接受这个误差（通常误差在半秒以内，可以接受）
- 或者对开头几秒做重编码：先用 `-c copy` 裁剪一个大范围，再用精确重编码裁剪头部

```bash
# 先粗切（从 I 帧开始）
ffmpeg -ss 00:01:30 -i input.mp4 -t 60 -c copy temp.mp4
# 再精确重编码头部 1 秒
ffmpeg -i temp.mp4 -ss 00:00:00 -t 45 -c:v libx264 -c:a aac output.mp4
```

## 补充9：FFmpeg 滤镜链示例

```bash
# 缩放 + 裁剪 + 添加文字水印
ffmpeg -i input.mp4 -vf "scale=1280:720,crop=1200:600:40:40,drawtext=text='Watermark':x=10:y=10:fontsize=24" output.mp4
```
