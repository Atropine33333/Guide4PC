《编译时的守则》

第一条：本机的 `int` 占四个字节。这条规矩在程序开始运行之前就要成立。
第二条：`sizeof(int)` 不等于 `4` 时，编译器不许放过这份代码。
第三条：守则写在文件作用域，用 `_Static_assert` 落笔；运行时打印的那一行，只把结果报给人看。
第四条：读入一个整数 `n`，照原样报出 `n`，再报出 `int` 的字节数与守则的核对结果。
第五条：不要把守则挪进函数里，也不要等程序跑起来才问它成不成立。

**人话**：在文件作用域写一条 `_Static_assert(sizeof(int) == 4, "int must be 4 bytes")`；读入十进制整数 `n`，输出一行 `n=<n> int=4 check=ok`。

**输入**：一行一个十进制整数 `n`，满足 `-2147483648 ≤ n ≤ 2147483647`。

**输出**：一行，形如 `n=42 int=4 check=ok`。`int=` 后面是 `sizeof(int)` 的十进制值，本机为 `4`；`check=` 后面是 `ok`。

### 示例

输入：

```text
42
```

输出：

```text
n=42 int=4 check=ok
```

### 约定

- `_Static_assert` 放在 `main` 之外的文件作用域，第二个参数是核对失败时显示的消息。
- 包含 `<assert.h>` 之后也可以写 `static_assert`；本题用 `_Static_assert` 即可。
- `sizeof(int)` 先转换成 `int`，再用 `%d` 输出。
- 输入保证落在 `int` 范围内，不会出现溢出。
- 输出行末不要有多余空格。
